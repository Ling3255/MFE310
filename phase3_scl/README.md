# Phase 3: supervised contrastive learning as the controlled improvement

This folder contains everything specific to phase 3 (E12–E16): the pre-registered plan, configs, step
scripts, jobs, tests and (after running) metadata, runs and results. Shared, reusable components live in
the core package `03_src/clinc_domain_aux/` (SupCon loss and class-balanced sampler in `contrastive.py`,
training options in `training.py`, `KNNDetector` in `detectors.py`, statistics in `confirmatory.py`).

**Research question.** Does adding supervised contrastive learning to BERT fine-tuning
((1−λ)·CE + λ·SupCon on the L2-normalised CLS vector) improve distance-based (Mahalanobis) OOS detection
without hurting intent classification, and does this hold under low resource and input noise?
Full design, hypotheses and decision rules: [`00_docs/01_experiment_plan.md`](00_docs/01_experiment_plan.md).

## Models (one fixed split, one protocol)

| Arm | Config | Role |
|---|---|---|
| B0 | `01_configs/baseline.yaml` | TF-IDF + logistic regression reference baseline |
| A `ce_balanced` | `01_configs/arm_ce_balanced.yaml` | BERT + cross-entropy, class-balanced batches (principal model) |
| B `scl` | `01_configs/generated/arm_scl_selected.yaml` | identical to A except the loss (controlled improvement; generated by step 02) |
| A′ `ce_standard` | `01_configs/arm_ce_standard.yaml` | sampler ablation (phase-1 random sampler) |
| R2 | `arm_ce_balanced_n{10,25}.yaml`, `generated/arm_scl_selected_n{10,25}.yaml` | low-resource arms |

## Fixed split (CLINC150 only; the official test set is not used)

Built by `04_steps/01_prepare_split.py` into `../dataset/clinc_phase3/{main,n10,n25}/`:
train = CLINC train minus the internal test (12,000); val = CLINC val + oos_val;
test = 20 held-out train utterances per intent (3,000) + 251 never-used OOS utterances
(`data_full` oos_train + `data_oos_plus`-only). Hashes, counts and leakage checks go to `07_metadata/`.

## How to run (student machine: Windows + RTX 4090, Git Bash, `trans` environment)

Run every command from the repository root. Expected layout: CLINC data at `../dataset/data`.

```bash
conda activate trans
export PYTHON_BIN=python
PYTHONPATH=03_src:phase3_scl/03_src python -m pytest 06_tests phase3_scl/06_tests -q   # expect 44 passed

bash phase3_scl/05_jobs/01_dev.sh       # J1: split, B0, 21 dev runs (seeds 100-102), selection on val
#   -> check phase3_scl/09_results/dev/selection.json, copy the chosen lambda/tau into plan section 13, push
bash phase3_scl/05_jobs/02_confirm.sh   # J2: A, B, A' x seeds 0-9 and R2 (n10, n25) x seeds 0-4
#   -> push runs and logs; supervisor reviews, then sets frozen: true + supervisor_approval in 01_configs/study.yaml
bash phase3_scl/05_jobs/03_evaluate.sh  # J3: ONE test evaluation, statistics, analysis (refuses a second run)

python phase3_scl/04_steps/06_demo_inference.py --text "what is my account balance" --text "who won the game last night"
```

Rules (pre-registered): never pass `--data-root` to the training step and never edit a config after its runs
started (the config hash is verified); do not drop or rerun a seed; if a step fails, report the error instead
of editing configs and rerunning.

## What to commit

Configs (including `01_configs/generated/`), `07_metadata/`, run records in `08_runs/*/` (checkpoints and
`.npz` files are git-ignored), `08_runs/job_logs/` (GPU/environment evidence), and `09_results/`

column of `09_results/analysis/cases.csv` by hand.
